⭐ HTTP Methods — In Depth

HTTP methods define what action the client wants the server to perform on a resource.

The most commonly used methods are:

GET
POST
PUT
PATCH
DELETE
HEAD
OPTIONS

Let’s break each one down clearly.

✅ 1. GET — Retrieve Data
Purpose:
Fetch data from the server.

Characteristics:

No request body
Safe (does not modify data)
Idempotent (multiple GETs = same result)
Can be cached
Parameters sent via URL query (e.g., ?id=10)

Example:
GET /users/10


Retrieves user with ID 10.

✅ 2. POST — Create Data
Purpose:
Send data to the server to create a new resource.

Characteristics:
Has request body (JSON, form data, etc.)
Not safe

Not idempotent
(multiple POSTs = multiple new entries)

Cannot be cached by default

Example Request Body:
{
"name": "Rajeev",
"email": "rajeev@mail.com"
}

Used For:
Creating a user
Submitting a form
Uploading files

✅ 3. PUT — Update/Replace Entire Resource
Purpose:

Update an entire resource or fully replace it.

Characteristics:
Idempotent
(1 or 10 PUTs → same result)
Requires complete data for update

Example:
PUT /users/10


Request body:

{
"name": "Rajeev",
"email": "rajeev@mail.com"
}


If you omit a field → it may get overwritten or deleted.

✅ 4. PATCH — Partial Update
Purpose:
Update specific fields of a resource.
Characteristics:
Not idempotent by strict definition (but often treated as idempotent)

Sends only the changes

Example:
PATCH /users/10


Body:
{
"email": "newemail@mail.com"
}


Only the email updates. Other fields remain the same.

✅ 5. DELETE — Remove a Resource
Purpose:

Delete a resource.

Characteristics:

Idempotent
(Deleting the same thing again returns 404 but doesn't change original action)
Body is usually not required.

Example:
DELETE /users/10


Output may be:
200 OK
204 No Content
404 Not Found

✅ 6. HEAD — Same as GET, but No Body
Purpose:

Check if a resource exists or get metadata without downloading content.

Characteristics:
Returns headers only
Used for performance optimization
Example use cases:
Check if a file exists
Check content length before downloading

✅ 7. OPTIONS — What is Allowed?
Purpose:

Ask the server which methods are allowed on a resource.
Characteristics:
Server returns Allow: header
Used heavily for CORS (Cross-Origin Resource Sharing)
Example Response:
Allow: GET, POST, OPTIONS
